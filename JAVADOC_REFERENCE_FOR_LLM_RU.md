# Справочник Javadoc для генерации кода LLM

> **Назначение**: Это исчерпывающий справочник для генерации doclint-совместимых Javadoc-комментариев в Java. Используйте это руководство, чтобы убедиться, что вся сгенерированная документация проходит валидацию `javadoc -Xdoclint:all`.

---

## Базовые принципы

### 1. Резюмирующее предложение (КРИТИЧНО)
- **ОБЯЗАТЕЛЬНО** заканчивается точкой (`.`), восклицательным знаком (`!`) или вопросительным знаком (`?`)
- Первое предложение = резюме (отображается в списках)
- Держите кратко (в идеале < 80 символов)
- Должно быть грамматически полным

### 2. Что vs Как
- Документируйте **что** делает код, НЕ **как** он это делает
- Фокус на контракте, поведении, побочных эффектах
- Избегайте деталей реализации

### 3. Обязательная документация
Каждый `public` и `protected` элемент ДОЛЖЕН иметь Javadoc:
- Классы, интерфейсы, перечисления, записи, аннотации
- Методы, конструкторы
- Поля (особенно public/protected/константы)
- Пакеты (через package-info.java)
- Модули (через module-info.java)

## Порядок тегов (СТРОГИЙ)

### Для классов/интерфейсов/enum/record/аннотаций:
```
1. @param (параметры типов, компоненты записей)
2. @see
3. @since
4. @deprecated
```

### Для методов/конструкторов:
```
1. @param (все параметры, включая параметры типов)
2. @return (только методы, НЕ void и НЕ конструкторы)
3. @throws/@exception (ВСЕ исключения)
4. @see
5. @since
6. @deprecated
```

**Примечание**: `@author` и `@version` **НЕ РЕКОМЕНДУЮТСЯ** в современной разработке (используйте Git).

## Правила HTML

### Разрешенные теги
- Абзацы: `<p>`, `</p>`
- Списки: `<ul>`, `<ol>`, `<li>`
- Форматирование: `<b>`, `<i>`, `<strong>`, `<em>`
- Разрывы строк: `<br>`
- Таблицы: `<table>`, `<tr>`, `<td>`, `<th>`
- Ссылки: `<a href="...">`

### КРИТИЧНО: Все теги ДОЛЖНЫ быть закрыты
```java
// ❌ ПЛОХО
/**
 * Возвращает <b>жирный текст
 * <p>Следующий абзац
 */

// ✅ ХОРОШО
/**
 * Возвращает <b>жирный текст</b>.
 * <p>
 * Следующий абзац.
 * </p>
 */
```

### Специальные символы
- Используйте `{@code}` для кода (авто-экранирует HTML)
- Используйте `{@literal}` для литерального текста со спец. символами
- Или экранируйте: `&lt;`, `&gt;`, `&amp;`

## Встроенные теги

### {@code текст}
- Отображается моноширинным шрифтом
- Авто-экранирует специальные символы HTML
- Используется для: фрагментов кода, идентификаторов, ключевых слов

```java
/**
 * Возвращает {@code true}, если {@code a < b}.
 */
```

### {@literal текст}
- Обычный шрифт (не моноширинный)
- Авто-экранирует HTML
- Используется для: специальных символов без семантики кода

### {@link Цель} и {@linkplain Цель}
- `{@link}` = моноширинная ссылка
- `{@linkplain}` = ссылка обычным шрифтом
- Синтаксис: `{@link Class#method(Type)}`

```java
/**
 * См. {@link java.util.List#add(Object)} для деталей.
 */
```

### {@value}
- Показывает значение константы
- `{@value}` = текущая константа
- `{@value Class#CONSTANT}` = ссылка на другую

### {@inheritDoc}
- Копирует документацию из переопределенного метода/интерфейса

### {@snippet} (Java 18+)
- Для многострочных примеров кода с подсветкой

## Правила для конкретных элементов

### Классы и интерфейсы

```java
/**
 * Однострочное резюме, заканчивающееся точкой.
 * <p>
 * Детальное описание, объясняющее назначение, использование и ограничения.
 * Несколько абзацев разделяются тегами {@code <p>}.
 * <p>
 * Потокобезопасность: Указать, является ли потокобезопасным или нет.
 *
 * @param <T> описание параметра типа с ограничениями
 * @since 1.0
 * @see RelatedClass
 */
public class MyClass<T extends Comparable<T>> {
}
```

**Критичные моменты**:
- Всегда указывайте потокобезопасность
- Документируйте все параметры типов с `@param <T>`
- Используйте `@since` для указания версии введения
- НЕ используйте `@author` или `@version` (если не требует организация)

### Перечисления (Enum)

```java
/**
 * Резюме класса перечисления.
 *
 * @since 1.0
 */
public enum Status {
    
    /**
     * Активный статус - пользователь может выполнять все операции.
     */
    ACTIVE,
    
    /**
     * Приостановленный статус - доступ пользователя временно отключен.
     */
    SUSPENDED;
    
    /**
     * Проверяет, разрешает ли этот статус вход.
     *
     * @return {@code true}, если вход разрешен, {@code false} в противном случае
     */
    public boolean allowsLogin() {
        return this == ACTIVE;
    }
}
```

**Каждая константа перечисления ДОЛЖНА быть документирована.**

### Записи (Record, Java 16+)

```java
/**
 * Резюме записи с назначением.
 * <p>
 * Записи неизменяемы и предоставляют автоматические реализации
 * {@code equals()}, {@code hashCode()} и {@code toString()}.
 *
 * @param id уникальный идентификатор, не должен быть null
 * @param name имя, не должно быть null или пустым
 * @throws NullPointerException если любой параметр null
 * @since 2.0
 */
public record User(String id, String name) {
    
    /**
     * Компактный конструктор с валидацией.
     *
     * @throws NullPointerException если id или name равен null
     * @throws IllegalArgumentException если name пустой
     */
    public User {
        if (id == null || name == null) {
            throw new NullPointerException("Параметры не могут быть null");
        }
        if (name.isEmpty()) {
            throw new IllegalArgumentException("Имя не может быть пустым");
        }
    }
}
```

**Документируйте компоненты записи с `@param` в Javadoc на уровне класса.**

### Аннотации

```java
/**
 * Резюме аннотации, объясняющее назначение и использование.
 * <p>
 * Пример использования:
 * <pre>{@code
 * @MyAnnotation(value = "test", timeout = 5000)
 * public void myMethod() { }
 * }</pre>
 *
 * @since 1.5
 */
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface MyAnnotation {
    
    /**
     * Описание атрибута value.
     * <p>
     * Не должно быть null или пустым. По умолчанию пустая строка.
     *
     * @return значение
     */
    String value() default "";
    
    /**
     * Таймаут в миллисекундах.
     * <p>
     * Должен быть положительным. По умолчанию 5000мс (5 секунд).
     *
     * @return таймаут в миллисекундах
     */
    long timeout() default 5000;
}
```

### Поля

```java
/**
 * Константы конфигурации.

public class Config {

     * <p>
     * Значение: {@value}

    /**

     * Должен быть положительным. По умолчанию {@value}.
     */

    /**
     * Текущий сеанс пользователя, или null, если не выполнен вход.
     * <p>
     * Это поле обновляется {@link #login(String)} и
     * очищается {@link #logout()}.
     */

}
```

### Методы

```java
/**
 * Однострочное резюме метода, заканчивающееся точкой.
 * <p>
 * Детальное описание того, что делает метод. Включите:
 * - Побочные эффекты (изменяет состояние, I/O, сетевые вызовы)
 * - Потокобезопасность
 * - Характеристики производительности, если релевантно
 * - Блокирующее поведение
 *
 * @param <T> описание параметра типа
 * @param param1 описание param1, ограничения (null/не null, диапазон, формат)
 * @param param2 описание param2, не должен быть null
 * @return описание возвращаемого значения, что оно представляет,
 *         специальные значения (null, пустое, -1), никогда не null / может быть null
 * @throws NullPointerException если param1 или param2 равен null
 * @throws IllegalArgumentException если param1 нарушает ограничения
 * @throws IOException если происходит ошибка I/O во время операции
 * @since 1.0
 */
public <T> Result<T> processData(String param1, List<T> param2) 
        throws IOException {
    // реализация
}
```

**Критично для методов**:
- Документируйте ВСЕ параметры (нет `@param` = ошибка doclint)
- Документируйте ВСЕ исключения (проверяемые И важные непроверяемые)
- Документируйте возвращаемое значение для не-void методов
- Указывайте обработку null: "не должен быть null" или "может быть null"
- Всегда указывайте "никогда не null" или "может быть null" для возвращаемых значений

### Геттеры и сеттеры

**ДА, документируйте их!** Уровень детализации зависит от сложности.

#### Простые геттеры/сеттеры
```java
/**
 * Возвращает адрес электронной почты пользователя.
 *
 * @return email, или null, если не установлен
 */
public String getEmail() { return email; }

/**
 * Устанавливает адрес электронной почты пользователя.
 *
 * @param email адрес электронной почты, может быть null
 * @throws IllegalArgumentException если формат email недопустим
 */
public void setEmail(String email) { this.email = email; }
```

#### Сложные геттеры (с вычислением/кэшированием)
```java
/**
 * Возвращает полное имя.
 * <p>
 * Конструирует имя из компонентов имени и фамилии.
 * Результат кэшируется после первого вычисления.
 *
 * @return полное имя, никогда не null, но может быть пустым
 */
public String getFullName() { }
```

#### Сложные сеттеры (с побочными эффектами)
```java
/**
 * Устанавливает статус пользователя.
 * <p>
 * Изменение статуса вызывает: обновление временной метки, очистку сеанса,
 * уведомление пользователя и аудит-логирование.
 *
 * @param status новый статус, не должен быть null
 * @throws NullPointerException если status равен null
 * @throws IllegalStateException если переход не разрешен
 */
public void setStatus(UserStatus status) { }
```

#### Булевы геттеры (is/has)
```java
/**
 * Проверяет, активна ли учетная запись.
 *
 * @return {@code true}, если активна, {@code false} в противном случае
 */
public boolean isActive() { }

/**
 * Проверяет, имеет ли пользователь привилегии администратора.
 *
 * @return {@code true}, если админ, {@code false} в противном случае
 */
public boolean hasAdminPrivileges() { }
```

#### Геттеры коллекций
```java
/**
 * Возвращает роли пользователя.
 * <p>
 * Возвращаемый список неизменяемый.
 *
 * @return неизменяемый список ролей, никогда не null, но может быть пустым
 */
public List<Role> getRoles() {
    return Collections.unmodifiableList(roles);
}
```

#### Плавные сеттеры (паттерн Builder)
```java
/**
 * Устанавливает адрес электронной почты.
 * <p>
 * Плавный сеттер для цепочки методов.
 *
 * @param email email, не должен быть null
 * @return этот экземпляр для цепочки методов
 * @throws NullPointerException если email равен null
 */
public User setEmail(String email) {
    this.email = email;
    return this;
}
```

**Ключевые моменты для геттеров/сеттеров:**
1. **Всегда указывайте обработку null**: "может быть null", "никогда не null", "или null, если не установлено"
2. **Документируйте правила валидации** в сеттерах
3. **Документируйте побочные эффекты** (уведомления, логирование, каскадные обновления)
4. **Документируйте потокобезопасность**, если обращаются к разделяемому состоянию
5. **Документируйте ограничения неизменяемости** ("не может быть изменено после первоначальной установки")
6. **Для булевых геттеров** используйте четкие описания true/false
7. **Для геттеров коллекций** указывайте, изменяема ли возвращаемая коллекция
8. **Документируйте производительность**, если геттер выполняет дорогое вычисление

### Пакет (package-info.java)

```java
/**

 *   <li>Функция 1</li>
 *   <li>Функция 2</li>
 *   <li>Функция 3</li>

 * <pre>{@code

package com.example.mypackage;
```

```java
module com.example.mymodule {
    exports com.example.api;
    exports com.example.model;
    requires java.logging;
}
```

## Частые ошибки doclint и исправления

### Ошибка: Отсутствующий @param
```java
// ❌ ПЛОХО - ошибка doclint: @param не найден
/**
 * Вычисляет сумму.
 * @return сумма
 */
public int add(int a, int b) { }

// ✅ ХОРОШО
/**
 * Вычисляет сумму двух целых чисел.
 *
 * @param a первое число
 * @param b второе число
 * @return сумма a и b
 */
public int add(int a, int b) { }
```

### Ошибка: Отсутствующий @return
```java
// ❌ ПЛОХО - ошибка doclint: @return не найден
/**
 * Получает имя пользователя.
 * @param id ID пользователя
 */
public String getName(int id) { }

// ✅ ХОРОШО
/**
 * Получает имя пользователя по ID.
 *
 * @param id ID пользователя
 * @return имя пользователя, или null, если не найдено
 */
public String getName(int id) { }
```

### Ошибка: Незакрытый HTML-тег
```java
// ❌ ПЛОХО - ошибка doclint: элемент не закрыт
/**
 * Возвращает <b>жирный текст
 */

// ✅ ХОРОШО
/**
 * Возвращает <b>жирный текст</b>.
 */
```

### Ошибка: Нет окончания резюмирующего предложения
```java
// ❌ ПЛОХО - нет точки в конце
/**
 * Вычисляет сумму
 */

// ✅ ХОРОШО
/**
 * Вычисляет сумму.
 */
```

### Ошибка: Недопустимая ссылка @link
```java
// ❌ ПЛОХО - ошибка doclint: ссылка не найдена
/**
 * @see MyClass#nonExistentMethod()
 */

// ✅ ХОРОШО - проверьте существование метода и соответствие сигнатуры
/**
 * @see MyClass#actualMethod(String)
 */
```

### Ошибка: Висячий Javadoc
```java
// ❌ ПЛОХО - пустая строка между комментарием и элементом
/**
 * Мой класс.
 */

public class MyClass { }

// ✅ ХОРОШО - нет пустой строки
/**
 * Мой класс.
 */
public class MyClass { }
```

## Документация исключений

**Документируйте ВСЕ исключения (проверяемые и непроверяемые):**

```java
/**
 * Обрабатывает платежную транзакцию.
 *
 * @param amount сумма платежа, должна быть положительной
 * @return чек транзакции
 * @throws NullPointerException если amount равна null
 * @throws IllegalArgumentException если amount отрицательна или нулевая
 * @throws PaymentException если обработка платежа не удалась
```

## Рекомендации по стилю написания

### Время и залог
- Используйте **настоящее время**: "Возвращает пользователя" (не "Вернет")
- Используйте **третье лицо**: "Вычисляет сумму" (не "Вычислите")
- Начинайте документацию методов с **глагола**: "Валидирует", "Создает", "Получает"

### Ясность
- Будьте **кратки**, но **полны**
- Избегайте избыточности
- Включайте все необходимые ограничения
- Указывайте диапазоны для числовых значений
- Упоминайте граничные случаи

### Примеры
```java
// ❌ ПЛОХО - слишком расплывчато
/**
 * Обрабатывает данные.

/**
```

## Быстрый чек-лист для LLM

При генерации Javadoc убедитесь:

- [ ] Резюмирующее предложение заканчивается точкой/восклицанием/вопросом
- [ ] Все теги `@param` присутствуют (соответствуют сигнатуре метода)
- [ ] `@return` присутствует для не-void методов
- [ ] Все исключения документированы с `@throws`
- [ ] Поведение null указано ("не должен быть null" / "может быть null" / "никогда не null")
- [ ] Все HTML-теги правильно закрыты
- [ ] Порядок тегов правильный (param → return → throws → see → since → deprecated)
- [ ] Потокобезопасность документирована для классов
- [ ] Параметры типов документированы с `@param <T>`
- [ ] Нет тегов `@author` или `@version` (если не запрошено явно)
- [ ] Компоненты записи документированы в Javadoc на уровне класса
- [ ] Все константы enum имеют Javadoc
- [ ] Примеры кода используют `{@code}` или `<pre>{@code}`
- [ ] Ссылки используют `{@link}` с правильным синтаксисом
- [ ] Нет пустых строк между Javadoc и элементом

---

## Резюме современных лучших практик

1. **НЕ используйте `@author`** - Git предоставляет лучшую историю
2. **НЕ используйте `@version`** - Используйте версионирование системы сборки
3. **ИСПОЛЬЗУЙТЕ `@since`** - Документируйте, когда функции были добавлены
4. **УКАЗЫВАЙТЕ обработку null** - Критично для контрактов API
5. **ДОКУМЕНТИРУЙТЕ потокобезопасность** - Предотвращает баги конкурентности
6. **ПРЕДОСТАВЛЯЙТЕ примеры** - Делает API легче понимаемым
7. **ДОКУМЕНТИРУЙТЕ побочные эффекты** - I/O, изменения состояния, сетевые вызовы
8. **ВАЛИДИРУЙТЕ с doclint** - Выявляйте ошибки рано
