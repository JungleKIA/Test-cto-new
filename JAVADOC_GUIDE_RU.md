## 1. Общие принципы и структура

### 1.1 Правило первого предложения

Первое предложение каждого Javadoc-комментария является **резюмирующим предложением**. Оно должно:
- Быть полным, грамматически правильным предложением
- Заканчиваться точкой (`.`), восклицательным знаком (`!`) или вопросительным знаком (`?`)
- Предоставлять краткий обзор документируемого элемента
- Отображаться в сводных списках и результатах поиска

**Правила:**
- Резюмирующее предложение заканчивается на первой точке, за которой следует пробел, табуляция или конец строки
- Используйте `{@literal .}`, если нужна точка, не завершающая резюме
- Держите его кратким (в идеале менее 80 символов)

**Пример:**
```java
/**
 * Вычисляет факториал заданного числа. Этот метод использует
 * итеративный подход для лучшей производительности.
 *
 * @param n число для вычисления факториала
 * @return результат вычисления факториала
 */
public long factorial(int n) {
    // реализация
}
```

### 1.2 Основное описание

После резюмирующего предложения предоставьте детальное описание:
- Используйте несколько предложений для объяснения функциональности, поведения и контекста
- Разделяйте абзацы тегами `<p>`
- Используйте списки (`<ul>`, `<ol>`) для структурированной информации
- Сосредоточьтесь на том, **что** делает код, а не **как**

**Пример:**
```java
/**
 * Управляет аутентификацией пользователей и отслеживанием сеансов.
 * <p>
 * Этот класс предоставляет методы для:
 * <ul>
 *   <li>Аутентификации пользователей через различные провайдеры идентификации</li>
 *   <li>Управления жизненным циклом сеанса и таймаутом</li>
 *   <li>Обработки процессов сброса пароля</li>
 * </ul>
 * <p>
 * Все методы этого класса являются потокобезопасными и могут быть вызваны
 * из нескольких потоков одновременно.
 */
public class AuthenticationManager {
    // реализация
}
```

### 1.3 Безопасное использование HTML-тегов

**Разрешенные HTML-теги** (наиболее распространенные):
- Абзацы: `<p>`, `</p>`
- Списки: `<ul>`, `<ol>`, `<li>`
- Форматирование текста: `<b>`, `<i>`, `<strong>`, `<em>`, `<code>`
- Разрывы строк: `<br>`
- Таблицы: `<table>`, `<tr>`, `<td>`, `<th>`
- Заголовки: `<h1>` до `<h6>`
- Ссылки: `<a href="...">`

**Важные правила:**
- Всегда закрывайте теги правильно (`<p>...</p>`)
- Используйте `{@code ...}` вместо `<code>` для фрагментов кода Java
- Не используйте устаревшие HTML-теги (`<font>`, `<center>` и т.д.)

### 1.4 Экранирование специальных символов

Специальные символы, требующие экранирования:
- `<` → используйте `&lt;` или `{@literal <}`
- `>` → используйте `&gt;` или `{@literal >}`
- `&` → используйте `&amp;` или `{@literal &}`
- `@` → используйте `{@literal @}` (когда не используется как тег)

**Пример:**
```java
/**
 * Сравнивает два значения, используя оператор {@literal <}.
 * Возвращает true, если {@code a < b}, иначе false.
 *
 * @param a первое значение
 * @param b второе значение
 * @return true, если a меньше b
 */
public boolean isLessThan(int a, int b) {
    return a < b;
}
```

## 2. Документирование классов и интерфейсов

### 2.1 Описание назначения

Каждый класс и интерфейс должны иметь Javadoc, объясняющий:
- **Что** он представляет или делает
- **Почему** он существует (его роль в системе)
- **Когда** его использовать
- Ключевые ограничения или предположения

### 2.2 Теги @author и @version - Современный подход

**Современный консенсус: Эти теги ОПЦИОНАЛЬНЫ и часто не рекомендуются.**

#### Почему @version проблематичен:

❌ **Избыточность**: Информация о версии должна управляться на уровне проекта/артефакта (Maven/Gradle)
❌ **Нагрузка на поддержку**: Требует ручного обновления (все забывают это делать)
❌ **Конфликты**: Дублирует версионирование системы сборки
❌ **Нет практической ценности**: История Git обеспечивает лучшее отслеживание

**Когда использовать @version:**
- ✅ Публичные API с формальной политикой версионирования
- ✅ Библиотеки с обязательствами семантического версионирования
- ✅ Когда явно требуется организационными стандартами

#### Почему @author проблематичен:

❌ **Быстро устаревает**: Код меняет владельцев, множество контрибьюторов
❌ **Контроль версий лучше**: Git blame/log предоставляет точную историю
❌ **Проблемы владения**: Может создавать ложное чувство "собственности"
❌ **Кошмар поддержки**: Кто обновляет при рефакторинге?

**Когда использовать @author:**
- ✅ Академический или образовательный код
- ✅ Когда требуется организационной политикой
- ✅ Кредит первоначальной реализации (но Git все равно лучше)

**Рекомендуемый подход:**
```java
/**
 * Управляет аутентификацией пользователей и отслеживанием сеансов.
 * <p>
 * Этот сервис обрабатывает аутентификацию через множество провайдеров,
 * включая OAuth2, SAML и устаревшую пару логин/пароль.
 * <p>
 * Потокобезопасен и разработан для высоконагруженных окружений.
 *
 * @since 1.0
 * @see AuthenticationProvider
 * @see SessionManager
 */
public class AuthenticationService {
    // реализация
}
```

### 2.3 Примеры использования

Включайте примеры кода для сложных классов:

```java
/**
 * Строитель для создания неизменяемых экземпляров {@link UserProfile}.
 * <p>
 * Этот строитель предоставляет плавный API для построения профилей
 * пользователей с валидацией и значениями по умолчанию.
 * <p>
 * Пример использования:
 * <pre>{@code
 * UserProfile profile = new UserProfileBuilder()
 *     .withUsername("john.doe")
 *     .withEmail("john@example.com")
 *     .withRole(Role.ADMIN)
 *     .build();
 * }</pre>
 *
 * @since 1.5
 * @see UserProfile
 */
public class UserProfileBuilder {
    // реализация
}
```

### 2.4 Документация интерфейсов

Документируйте интерфейсы с акцентом на контракт и ожидания:

```java
/**
 * Определяет контракт для операций сохранения данных.
 * <p>
 * Реализации этого интерфейса должны гарантировать, что:
 * <ul>
 *   <li>Все операции атомарны</li>
 *   <li>Неудачные операции вызывают специфические исключения</li>
 *   <li>Null-значения обрабатываются согласно документации метода</li>
 * </ul>
 * <p>
 * Реализации должны быть потокобезопасными, если явно не указано иное.
 *
 * @param <T> тип сущности, управляемой этим репозиторием
 * @since 1.0
 * @see Repository
 */
public interface DataRepository<T> {
    // объявления методов
}
```

## 3. Документирование перечислений (Enum)

### 3.1 Документация класса перечисления

Документируйте общую цель и использование перечисления:

```java
/**
 * Определяет возможные состояния учетной записи пользователя.
 * <p>
 * Эти состояния контролируют, какие операции может выполнять пользователь
 * и как система взаимодействует с учетной записью. Переходы состояний
 * управляются {@link AccountService}.
 *
 * @since 1.0
 * @see AccountService#changeStatus(Account, AccountStatus)
 */
public enum AccountStatus {
    // константы
}
```

### 3.2 Документация констант перечисления

**Каждая константа перечисления должна быть документирована:**

```java
/**
 * Определяет методы HTTP-запросов согласно RFC 7231.
 *
 * @since 1.0
 * @see <a href="https://tools.ietf.org/html/rfc7231#section-4">RFC 7231 Section 4</a>
 */
public enum HttpMethod {
    
    /**
     * Метод GET запрашивает передачу текущего выбранного представления
     * для целевого ресурса.
     * <p>
     * GET является основным механизмом для извлечения информации и считается
     * безопасным и идемпотентным.
     */
    GET,
    
    /**
     * Метод POST запрашивает, чтобы целевой ресурс обработал представление,
     * заключенное в запросе.
     * <p>
     * POST обычно используется для создания новых ресурсов. Он ни безопасен,
     * ни идемпотентен.
     */
    POST,
    
    /**
     * Метод PUT запрашивает, чтобы состояние целевого ресурса было создано
     * или заменено состоянием, определенным представлением.
     * <p>
     * PUT идемпотентен, но не безопасен.
     */
    PUT,
    
    /**
     * Метод DELETE запрашивает удаление целевого ресурса.
     * <p>
     * DELETE идемпотентен, но не безопасен.
     */
    DELETE,
    
    /**
     * Метод PATCH запрашивает, чтобы набор изменений, описанных в запросе,
     * был применен к целевому ресурсу.
     * <p>
     * PATCH ни безопасен, ни идемпотентен.
     */
    PATCH;
    
    /**
     * Проверяет, является ли данный HTTP-метод идемпотентным.
     * <p>
     * Идемпотентный метод производит одинаковый результат при многократном
     * вызове с теми же параметрами.
     *
     * @return {@code true}, если метод идемпотентен, {@code false} в противном случае
     */
    public boolean isIdempotent() {
        return this == GET || this == PUT || this == DELETE;
    }
}
```

### 3.3 Перечисления с полями и методами

Документируйте дополнительные члены:

```java
/**
 * Коды статуса HTTP согласно RFC 7231 и связанным спецификациям.
 *
 * @since 1.0
 */
public enum HttpStatus {
    
    /**
     * 200 OK - Запрос выполнен успешно.
     */
    OK(200, "OK"),
    
    /**
     * 201 Created - Запрос выполнен, и в результате создан новый ресурс.
     */
    CREATED(201, "Created"),
    
    /**
     * 400 Bad Request - Запрос не может быть понят сервером из-за
     * неправильного синтаксиса.
     */
    BAD_REQUEST(400, "Bad Request"),
    
    /**
     * 404 Not Found - Сервер не нашел ничего, соответствующего Request-URI.
     */
    NOT_FOUND(404, "Not Found"),
    
    /**
     * 500 Internal Server Error - Сервер столкнулся с неожиданным условием,
     * которое помешало выполнению запроса.
     */
    INTERNAL_SERVER_ERROR(500, "Internal Server Error");
    
    /**
     * Числовой код статуса.
     */
    private final int code;
    
    /**
     * Фраза-причина, связанная с этим кодом статуса.
     */
    private final String reasonPhrase;
    
    /**
     * Создает новый статус HTTP с указанным кодом и фразой-причиной.
     *
     * @param code числовой код статуса
     * @param reasonPhrase текстовая фраза-причина
     */
    HttpStatus(int code, String reasonPhrase) {
        this.code = code;
        this.reasonPhrase = reasonPhrase;
    }
    
    /**
     * Возвращает числовой код статуса.
     *
     * @return код статуса
     */
    public int getCode() {
        return code;
    }
    
    /**
     * Возвращает фразу-причину, связанную с этим кодом статуса.
     *
     * @return фразу-причину, никогда не null
     */
    public String getReasonPhrase() {
        return reasonPhrase;
    }
    
    /**
     * Проверяет, представляет ли этот код статуса успешный ответ (2xx).
     *
     * @return {@code true}, если код статуса между 200 и 299 включительно
     */
    public boolean isSuccessful() {
        return code >= 200 && code < 300;
    }
}
```

## 4. Документирование записей (Record)

Записи (введены в Java 14, финализированы в Java 16) — это специальные классы для неизменяемых данных. Они требуют специфических подходов к документированию.

### 4.1 Документация класса записи

```java
/**
 * Представляет неизменяемую точку в 2D пространстве.
 * <p>
 * Эта запись обеспечивает компактное представление координатной пары
 * с автоматическими реализациями {@code equals()}, {@code hashCode()}
 * и {@code toString()}.
 * <p>
 * Пример использования:
 * <pre>{@code
 * Point p1 = new Point(10, 20);
 * Point p2 = new Point(10, 20);
 * assert p1.equals(p2); // true
 * }</pre>
 *
 * @param x x-координата, может быть любым значением double, включая бесконечность
 * @param y y-координата, может быть любым значением double, включая бесконечность
 * @since 2.0
 */
public record Point(double x, double y) {
    // компактный конструктор или методы
}
```

**Важно для записей:**
- Документируйте компоненты записи, используя теги `@param` в Javadoc на уровне класса
- Они автоматически применяются к каноническому конструктору и методам-аксессорам

### 4.2 Запись с валидацией (компактный конструктор)

```java
/**
 * Представляет адрес электронной почты с валидацией.
 * <p>
 * Эта запись гарантирует, что адрес электронной почты соответствует базовым
 * требованиям формата. Валидация выполняется в компактном конструкторе.
 *
 * @param address строка адреса электронной почты, не должна быть null или пустой
 *                и должна содержать ровно один символ {@literal @}
 * @throws NullPointerException если address равен null
 * @throws IllegalArgumentException если address пустой или имеет неверный формат
 * @since 2.1
 */
public record Email(String address) {
    
    /**
     * Компактный конструктор, валидирующий формат адреса электронной почты.
     *
     * @throws NullPointerException если address равен null
     * @throws IllegalArgumentException если address пустой или неверный
     */
    public Email {
        if (address == null) {
            throw new NullPointerException("Адрес электронной почты не может быть null");
        }
        if (address.isBlank()) {
            throw new IllegalArgumentException("Адрес электронной почты не может быть пустым");
        }
        if (address.chars().filter(ch -> ch == '@').count() != 1) {
            throw new IllegalArgumentException("Неверный формат электронной почты");
        }
    }
    
    /**
     * Возвращает доменную часть адреса электронной почты.
     * <p>
     * Например, для "user@example.com" возвращает "example.com".
     *
     * @return доменную часть, никогда не null или пустую
     */
    public String domain() {
        return address.substring(address.indexOf('@') + 1);
    }
}
```

### 4.3 Запись с пользовательскими методами

```java
/**
 * Представляет рациональное число в виде неизменяемой дроби.
 * <p>
 * Эта запись хранит числитель и знаменатель и обеспечивает,
 * что дробь всегда в упрощенной форме с положительным знаменателем.
 *
 * @param numerator числитель дроби
 * @param denominator знаменатель дроби, не должен быть нулем
 * @throws IllegalArgumentException если denominator равен нулю
 * @since 2.0
 */
public record Rational(int numerator, int denominator) {
    
    /**
     * Канонический конструктор, нормализующий дробь.
     * <p>
     * Гарантирует, что знаменатель положительный и сокращает дробь
     * до наименьших членов.
     *
     * @throws IllegalArgumentException если denominator равен нулю
     */
    public Rational {
        if (denominator == 0) {
            throw new IllegalArgumentException("Знаменатель не может быть нулем");
        }
        
        // Нормализация: обеспечение положительного знаменателя
        if (denominator < 0) {
            numerator = -numerator;
            denominator = -denominator;
        }
        
        // Сокращение до наименьших членов
        int gcd = gcd(Math.abs(numerator), denominator);
        numerator /= gcd;
        denominator /= gcd;
    }
    
    /**
     * Складывает это рациональное число с другим.
     *
     * @param other рациональное число для сложения, не должно быть null
     * @return новое {@code Rational}, представляющее сумму
     * @throws NullPointerException если other равен null
     */
    public Rational add(Rational other) {
        return new Rational(
            this.numerator * other.denominator + other.numerator * this.denominator,
            this.denominator * other.denominator
        );
    }
    
    /**
     * Вычисляет наибольший общий делитель, используя алгоритм Евклида.
     *
     * @param a первое число, должно быть неотрицательным
     * @param b второе число, должно быть неотрицательным
     * @return НОД a и b
     */
    private static int gcd(int a, int b) {
        return b == 0 ? a : gcd(b, a % b);
    }
}
```

## 5. Документирование аннотаций

Аннотации требуют документации для самой аннотации и каждого из её элементов.

### 5.1 Маркерная аннотация (без элементов)

```java
/**
 * Указывает, что метод не должен вызываться напрямую кодом приложения.
 * <p>
 * Эта аннотация служит документацией, что метод предназначен только
 * для использования фреймворком или инфраструктурой. Методы, помеченные
 * этой аннотацией, могут иметь специальные требования или побочные эффекты.
 * <p>
 * Пример использования:
 * <pre>{@code
 * @Internal
 * public void initializeFramework() {
 *     // инициализация фреймворка
 * }
 * }</pre>
 *
 * @since 1.5
 */
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Internal {
}
```

### 5.2 Аннотация с одним значением

```java
/**
 * Указывает максимальное количество попыток повтора для операции.
 * <p>
 * Эта аннотация может применяться к методам для настройки автоматического
 * поведения повтора в случае временных сбоев.
 * <p>
 * Пример использования:
 * <pre>{@code
 * @MaxRetries(3)
 * public void connectToDatabase() {
 *     // логика подключения
 * }
 * }</pre>
 *
 * @since 2.0
 * @see RetryPolicy
 */
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface MaxRetries {
    
    /**
     * Максимальное количество попыток повтора.
     * <p>
     * Должно быть неотрицательным целым числом. Значение 0 означает отсутствие
     * повторов (немедленный отказ при первой ошибке).
     *
     * @return максимальное количество повторов
     */
    int value();
}
```

### 5.3 Аннотация с несколькими элементами

```java
/**
 * Настраивает поведение кэширования для метода или класса.
 * <p>
 * Эта аннотация включает автоматическое кэширование результатов методов
 * с настраиваемым временем истечения и стратегиями генерации ключей.
 * <p>
 * Пример использования:
 * <pre>{@code
 * @Cacheable(
 *     key = "user",
 *     ttl = 3600,
 *     unit = TimeUnit.SECONDS
 * )
 * public User findUserById(Long id) {
 *     return database.query(id);
 * }
 * }</pre>
 *
 * @since 2.5
 * @see CacheManager
 */
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.METHOD, ElementType.TYPE})
public @interface Cacheable {
    
    /**
     * Префикс ключа кэша.
     * <p>
     * Это значение комбинируется с параметрами метода для генерации
     * уникальных ключей кэша. Если пусто, используется полное имя метода.
     *
     * @return префикс ключа кэша
     */
    String key() default "";
    
    /**
     * Время жизни для кэшированных значений.
     * <p>
     * После этой длительности кэшированные значения считаются устаревшими
     * и будут пересчитаны. Должно быть положительным.
     *
     * @return значение TTL
     */
    long ttl() default 300;
    
    /**
     * Единица времени для значения TTL.
     *
     * @return единица времени, никогда не null
     */
    TimeUnit unit() default TimeUnit.SECONDS;
    
    /**
     * Нужно ли кэшировать null значения.
     * <p>
     * Если {@code false}, методы, возвращающие null, не будут кэшироваться
     * и будут вызываться при каждом обращении.
     *
     * @return {@code true} для кэширования null значений, {@code false} в противном случае
     */
    boolean cacheNulls() default false;
    
    /**
     * Условия, при которых должно применяться кэширование.
     * <p>
     * Это SpEL-выражение, вычисляемое во время выполнения. Кэширование
     * происходит только если выражение вычисляется в {@code true}.
     *
     * @return выражение условия, пустая строка означает всегда кэшировать
     */
    String condition() default "";
}
```

### 5.4 Аннотация с элементами-массивами

```java
/**
 * Указывает роли, необходимые для доступа к ресурсу или выполнения метода.
 * <p>
 * Эта аннотация используется для декларативной конфигурации безопасности.
 * Пользователь должен иметь хотя бы одну из указанных ролей.
 * <p>
 * Пример использования:
 * <pre>{@code
 * @RequiresRoles({"ADMIN", "MANAGER"})
 * public void deleteUser(Long userId) {
 *     userRepository.delete(userId);
 * }
 * }</pre>
 *
 * @since 1.0
 * @see SecurityContext
 */
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.METHOD, ElementType.TYPE})
public @interface RequiresRoles {
    
    /**
     * Роли, необходимые для доступа к аннотированному элементу.
     * <p>
     * Пользователь должен иметь хотя бы одну из этих ролей. Пустой массив
     * означает, что роли не требуются (эквивалентно публичному доступу).
     * <p>
     * Имена ролей чувствительны к регистру и должны соответствовать ролям,
     * определенным в вашей конфигурации безопасности.
     *
     * @return массив необходимых имен ролей, никогда не null, но может быть пустым
     */
    String[] value();
    
    /**
     * Должен ли пользователь иметь ВСЕ указанные роли (логика И)
     * или только ОДНУ из них (логика ИЛИ).
     * <p>
     * По умолчанию используется логика ИЛИ (пользователю нужна любая одна роль).
     *
     * @return {@code true} для логики И, {@code false} для логики ИЛИ
     */
    boolean requireAll() default false;
}
```

## 7. Документирование методов и конструкторов

### 7.1 Описывайте что, а не как

Сосредоточьтесь на контракте метода и поведении, а не на деталях реализации:

**Плохо:**
```java
/**
 * Проходит по массиву в цикле и добавляет каждый элемент к переменной суммы.
 */
public int calculateSum(int[] numbers) {
    // реализация
}
```

**Хорошо:**
```java
/**
 * Вычисляет сумму всех элементов в заданном массиве.
 *
 * @param numbers массив чисел для суммирования, не должен быть null
 * @return сумма всех элементов, или 0 если массив пустой
 * @throws NullPointerException если numbers равен null
 */
public int calculateSum(int[] numbers) {
    // реализация
}
```

### 7.2 Побочные эффекты и особенности поведения

Всегда документируйте:
- Характеристики потокобезопасности
- Изменения параметров или состояния объекта
- Сетевые операции или операции ввода-вывода
- Длительные операции
- Поведение кэширования

**Пример:**
```java
/**
 * Отправляет уведомление по электронной почте указанному получателю.
 * <p>
 * Этот метод выполняет сетевой ввод-вывод и может блокироваться на несколько секунд.
 * Рассмотрите вызов из фонового потока для лучшей отзывчивости.
 * <p>
 * Этот метод потокобезопасен и может быть вызван одновременно
 * из нескольких потоков.
 *
 * @param recipient адрес электронной почты получателя, не должен быть null или пустым
 * @param subject тема письма, не должна быть null
 * @param body содержимое тела письма, не должно быть null
 * @throws IllegalArgumentException если recipient не является допустимым адресом электронной почты
 * @throws EmailServiceException если письмо не может быть отправлено из-за
 *         сетевых ошибок или ошибок сервиса
 */
public void sendEmail(String recipient, String subject, String body) {
    // реализация
}
```

### 7.3 Детальное документирование @param

Каждый тег `@param` должен:
- Описывать, что представляет параметр
- Указывать ограничения (null/не null, диапазон, формат)
- Объяснять роль параметра в операции

**Пример:**
```java
/**
 * Создает новую учетную запись пользователя с указанными данными.

 * @param username уникальное имя пользователя для учетной записи, не должно быть null,
 *                 должно содержать от 3 до 20 символов и состоять только из
 *                 буквенно-цифровых символов и подчеркиваний
 * @param email адрес электронной почты пользователя, не должен быть null и должен
 *              соответствовать допустимому формату email
 * @param age возраст пользователя в годах, должен быть от 13 до 150 (включительно)
 * @return вновь созданная учетная запись пользователя с сгенерированным ID
 * @throws IllegalArgumentException если какой-либо параметр нарушает свои ограничения
 * @throws DuplicateUsernameException если имя пользователя уже занято
 */
public UserAccount createUser(String username, String email, int age) {
    // реализация
}
```

Документируйте возвращаемое значение, включая:
- Что оно представляет
- Возможные специальные значения (null, пустое, -1 и т.д.)
- Граничные случаи
- Когда может быть возвращено null или пустое значение

**Пример:**
```java
/**

 *         с данным именем не существует

/**
```

### 7.5 Полное документирование @throws

Документируйте **все** исключения, которые может выбросить метод:
- **Проверяемые исключения**: должны быть документированы
- **Непроверяемые исключения**: должны быть документированы, если они являются частью контракта
- Включайте **условие**, вызывающее каждое исключение

**Пример:**
```java
/**

 * @throws InsufficientFundsException если баланс счета меньше
 *         запрошенной суммы
 * @throws PaymentProcessingException если платеж не может быть обработан
 *         из-за системной ошибки
 */
public Receipt processPayment(String accountId, BigDecimal amount, String currency)
        throws AccountNotFoundException, InsufficientFundsException,
               PaymentProcessingException {
    // реализация
}
```

### 7.7 Документирование геттеров и сеттеров

Геттеры и сеттеры **должны быть документированы**, но уровень детализации зависит от их сложности.

#### Простые геттеры

Для **простых геттеров** (прямой доступ к полю без логики) предоставьте краткую документацию:

**Минимум требуемого:**
```java
/**
 * Возвращает адрес электронной почты пользователя.
 *
 * @return адрес электронной почты, или null, если не установлен
 */
public String getEmail() {
    return email;
}
```

**Лучше с деталями:**
```java
/**
 * Возвращает адрес электронной почты пользователя.
 * <p>
 * Адрес электронной почты валидируется при установке и гарантированно
 * в допустимом формате, если не null.
 *
 * @return адрес электронной почты, или null, если не установлен
 */
public String getEmail() {
    return email;
}
```

#### Простые сеттеры

Для **простых сеттеров** (прямое присваивание полю) документируйте ограничения и валидацию:

**Минимум требуемого:**
```java
/**
 * Устанавливает адрес электронной почты пользователя.
 *
 * @param email адрес электронной почты, может быть null
 */
public void setEmail(String email) {
    this.email = email;
}
```

**Лучше с правилами валидации:**
```java
/**
 * Устанавливает адрес электронной почты пользователя.
 * <p>
 * Адрес должен быть в допустимом формате (user@domain.tld).
 * Установка null очищает адрес электронной почты.
 *
 * @param email адрес электронной почты, может быть null для очистки
 * @throws IllegalArgumentException если email не null и имеет недопустимый формат
 */
public void setEmail(String email) {
    if (email != null && !isValidEmail(email)) {
        throw new IllegalArgumentException("Недопустимый формат email");
    }
    this.email = email;
}
```

#### Сложные геттеры

Для геттеров с **вычислением, кэшированием или ленивой инициализацией**:

```java
/**
 * Возвращает полное имя пользователя.
 * <p>
 * Этот метод конструирует полное имя из компонентов имени и фамилии.
 * Если любой из компонентов null, возвращает только ненулевую часть.
 * Если оба null, возвращает пустую строку.
 * <p>
 * Результат кэшируется после первого вычисления для производительности.
 *
 * @return полное имя, никогда не null, но может быть пустым
 */
public String getFullName() {
    if (fullNameCache == null) {
        fullNameCache = buildFullName();
    }
    return fullNameCache;
}
```

#### Сложные сеттеры

Для сеттеров с **валидацией, побочными эффектами или каскадными обновлениями**:

```java
/**
 * Устанавливает статус пользователя.
 * <p>
 * Изменение статуса вызывает несколько побочных эффектов:
 * <ul>
 *   <li>Обновляет временную метку последнего изменения</li>
 *   <li>Очищает сеанс, если статус SUSPENDED или INACTIVE</li>
 *   <li>Отправляет уведомление пользователю при изменении статуса</li>
 *   <li>Логирует изменение статуса для аудита</li>
 * </ul>
 * <p>
 * Этот метод потокобезопасен, но может кратковременно блокироваться
 * для доставки уведомления.
 *
 * @param status новый статус, не должен быть null
 * @throws NullPointerException если status равен null
 * @throws IllegalStateException если текущий статус не позволяет переход
 *         к новому статусу
 */
public void setStatus(UserStatus status) {
    validateStatusTransition(this.status, status);
    this.status = status;
    this.lastModified = Instant.now();
    handleStatusChange(status);
}
```

#### Булевы геттеры (префиксы is/has)

Булевы геттеры обычно используют префиксы `is` или `has`:

```java
/**
 * Проверяет, активна ли учетная запись пользователя.
 * <p>
 * Учетная запись считается активной, если статус ACTIVE
 * и учетная запись не истекла.
 *
 * @return {@code true}, если учетная запись активна, {@code false} в противном случае
 */
public boolean isActive() {
    return status == Status.ACTIVE && !isExpired();
}

/**
 * Проверяет, имеет ли пользователь административные привилегии.
 *
 * @return {@code true}, если пользователь админ, {@code false} в противном случае
 */
public boolean hasAdminPrivileges() {
    return role == Role.ADMIN || role == Role.SUPER_ADMIN;
}
```

#### Геттеры коллекций

Для геттеров, возвращающих коллекции, указывайте изменяемость:

```java
/**
 * Возвращает список ролей пользователя.
 * <p>

 *

public List<Role> getRoles() {
```

**С защитной копией:**
```java
/**
```

Для сеттеров, возвращающих `this` для цепочки вызовов:

```java
/**
```

#### Полный пример: JavaBean с геттерами/сеттерами

```java
/**
 * Представляет учетную запись пользователя в системе.
 * <p>
 * Это изменяемый JavaBean со стандартными методами getter/setter.
 * Все сеттеры валидируют свой ввод перед присваиванием.
 *
 * @since 1.0
 */
public class User {
    
    private String id;
    private String username;
    private String email;
    private UserStatus status;
    private Instant createdAt;
    
    /**
     * Возвращает уникальный идентификатор пользователя.
     *
     * @return ID пользователя, никогда не null после сохранения
     */
    public String getId() {
        return id;
    }
    
    /**
     * Устанавливает уникальный идентификатор пользователя.
     * <p>
     * Должен вызываться только слоем персистентности.
     *
     * @param id ID пользователя, не должен быть null
     * @throws NullPointerException если id равен null
     */
    public void setId(String id) {
        if (id == null) {
            throw new NullPointerException("ID не может быть null");
        }
        this.id = id;
    }
    
    /**
     * Возвращает имя пользователя.
     * <p>
     * Имя пользователя уникально в системе и не может быть изменено
     * после первоначальной установки.
     *
     * @return имя пользователя, никогда не null
     */
    public String getUsername() {
        return username;
    }
    
    /**
     * Устанавливает имя пользователя.
     * <p>
     * Имя пользователя должно содержать 3-20 буквенно-цифровых символов.
     * Этот метод должен вызываться только при создании пользователя.
     *
     * @param username имя пользователя, не должно быть null
     * @throws NullPointerException если username равен null
     * @throws IllegalArgumentException если username не соответствует требованиям
     * @throws IllegalStateException если username уже установлено
     */
    public void setUsername(String username) {
        if (username == null) {
            throw new NullPointerException("Username не может быть null");
        }
        if (this.username != null) {
            throw new IllegalStateException("Username уже установлено");
        }
        validateUsername(username);
        this.username = username;
    }
    
    /**
     * Возвращает адрес электронной почты.
     *
     * @return адрес электронной почты, или null, если не установлен
     */
    public String getEmail() {
        return email;
    }
    
    /**
     * Устанавливает адрес электронной почты.
     * <p>
     * Email должен быть в допустимом формате. Установка null очищает email.
     *
     * @param email адрес электронной почты, может быть null
     * @throws IllegalArgumentException если email не null и недопустим
     */
    public void setEmail(String email) {
        if (email != null && !isValidEmail(email)) {
            throw new IllegalArgumentException("Недопустимый формат email");
        }
        this.email = email;
    }
    
    /**
     * Возвращает текущий статус учетной записи.
     *
     * @return статус, никогда не null
     */
    public UserStatus getStatus() {
        return status;
    }
    
    /**
     * Устанавливает статус учетной записи.
     * <p>
     * Переходы статусов валидируются. Не все переходы разрешены.
     * См. {@link UserStatus} для допустимых переходов.
     *
     * @param status новый статус, не должен быть null
     * @throws NullPointerException если status равен null
     * @throws IllegalStateException если переход не разрешен
     */
    public void setStatus(UserStatus status) {
        if (status == null) {
            throw new NullPointerException("Status не может быть null");
        }
        validateStatusTransition(this.status, status);
        this.status = status;
    }
    
    /**
     * Возвращает временную метку создания учетной записи.
     *
     * @return время создания, никогда не null после сохранения
     */
    public Instant getCreatedAt() {
        return createdAt;
    }
    
    /**
     * Устанавливает временную метку создания учетной записи.
     * <p>
     * Должен вызываться только слоем персистентности.
     *
     * @param createdAt время создания, не должно быть null
     * @throws NullPointerException если createdAt равен null
     */
    public void setCreatedAt(Instant createdAt) {
        if (createdAt == null) {
            throw new NullPointerException("CreatedAt не может быть null");
        }
        this.createdAt = createdAt;
    }
    
    /**
     * Проверяет, активна ли учетная запись в данный момент.
     *
     * @return {@code true}, если статус ACTIVE, {@code false} в противном случае
     */
    public boolean isActive() {
        return status == UserStatus.ACTIVE;
    }
}
```

#### Ключевые моменты для геттеров/сеттеров

1. **Всегда документируйте обработку null**: "может быть null", "никогда не null", "или null, если не установлено"
2. **Документируйте правила валидации** в сеттерах
3. **Документируйте побочные эффекты** (уведомления, логирование, каскадные обновления)
4. **Документируйте потокобезопасность**, если геттеры/сеттеры обращаются к разделяемому состоянию
5. **Документируйте ограничения неизменяемости** (например, "не может быть изменено после первоначальной установки")
6. **Для булевых геттеров** используйте четкие описания true/false
7. **Для геттеров коллекций** указывайте, изменяема ли возвращаемая коллекция
8. **Документируйте характеристики производительности**, если геттер выполняет дорогое вычисление

### 8.3 Ограниченные параметры типов

```java
/**
 * Отсортированная коллекция, поддерживающая элементы в естественном порядке.
 * <p>
 * Элементы должны реализовывать {@link Comparable} для добавления в эту
 * коллекцию. Коллекция использует естественный порядок, определенный
 * {@link Comparable#compareTo(Object)}.
 *
 * @param <E> тип элементов, должен быть сравнимым
 * @since 1.0
 */
public class SortedList<E extends Comparable<E>> {
    
    private final List<E> elements = new ArrayList<>();
    
    /**
     * Добавляет элемент в коллекцию с сохранением сортировки.
     * <p>
     * Элемент вставляется в соответствующую позицию для поддержания
     * порядка сортировки. Эта операция имеет сложность O(n) из-за вставки.
     *
     * @param element элемент для добавления, не должен быть null
     * @throws NullPointerException если element равен null
     */
    public void add(E element) {
        if (element == null) {
            throw new NullPointerException("Элемент не может быть null");
        }
        
        int insertionPoint = Collections.binarySearch(elements, element);
        if (insertionPoint < 0) {
            insertionPoint = -(insertionPoint + 1);
        }
        elements.add(insertionPoint, element);
    }
}
```

### 8.4 Параметры типов на уровне метода

```java
/**
 * Утилитные методы для работы с коллекциями.
 */
public class CollectionUtils {
    
    /**
     * Находит первый элемент в коллекции, соответствующий предикату.
     * <p>
     * Этот метод итерируется по коллекции и возвращает первый
     * элемент, для которого предикат возвращает {@code true}.
     *
     * @param <T> тип элементов в коллекции
     * @param collection коллекция для поиска, не должна быть null
     * @param predicate условие для проверки, не должен быть null
     * @return первый соответствующий элемент, или null, если совпадение не найдено
     * @throws NullPointerException если collection или predicate равен null
     */
    public static <T> T findFirst(Collection<T> collection, Predicate<T> predicate) {
        for (T element : collection) {
            if (predicate.test(element)) {
                return element;
            }
        }
        return null;
    }
    
    /**
     * Преобразует каждый элемент исходного списка, используя предоставленную функцию.
     * <p>
     * Создает новый список, содержащий преобразованные элементы. Исходный
     * список не изменяется.
     *
     * @param <S> тип элементов в исходном списке
     * @param <T> тип элементов в результирующем списке
     * @param source исходный список, не должен быть null
     * @param mapper функция преобразования, не должна быть null
     * @return новый список с преобразованными элементами, никогда не null
     * @throws NullPointerException если source или mapper равен null
     */
    public static <S, T> List<T> map(List<S> source, Function<S, T> mapper) {
        List<T> result = new ArrayList<>(source.size());
        for (S element : source) {
            result.add(mapper.apply(element));
        }
        return result;
    }
}
```

Документация модулей (Java 9+) описывает цель модуля, зависимости и экспорты.

### 10.1 Базовая документация модуля

```java
/**
 * Основная доменная модель и бизнес-логика.
 * <p>
 * Этот модуль содержит фундаментальные доменные сущности и сервисы
 * для приложения. Он не имеет зависимостей от инфраструктуры
 * или проблем представления.
 * <p>
 * Экспортируемые пакеты:
 * <ul>
 *   <li>{@code com.example.domain.model} - Доменные сущности</li>
 *   <li>{@code com.example.domain.service} - Доменные сервисы</li>
 *   <li>{@code com.example.domain.repository} - Интерфейсы репозиториев</li>
 * </ul>
 *
 * @since 3.0
 */
module com.example.domain {
    exports com.example.domain.model;
    exports com.example.domain.service;
    exports com.example.domain.repository;
    
    requires java.logging;
}
```

### 10.2 Модуль с квалифицированными экспортами

```java
/**
 * Реализация слоя доступа к данным.
 * <p>
 * Этот модуль предоставляет конкретные реализации интерфейсов
 * репозиториев, используя JPA/Hibernate. Он включает:
 * <ul>
 *   <li>Маппинги сущностей JPA</li>
 *   <li>Реализации репозиториев</li>
 *   <li>Скрипты миграции базы данных</li>
 *   <li>Управление транзакциями</li>
 * </ul>
 * <p>
 * Пакет {@code com.example.data.internal} экспортируется только
 * в тестовый модуль и не должен использоваться кодом приложения.
 * <p>
 * Поддержка баз данных:
 * <ul>
 *   <li>PostgreSQL 12+</li>
 *   <li>MySQL 8.0+</li>
 *   <li>H2 (для тестирования)</li>
 * </ul>
 *
 * @since 3.0
 */
module com.example.data {
    requires transitive com.example.domain;
    requires java.persistence;
    requires org.hibernate.orm.core;
    requires java.sql;
    
    exports com.example.data.repository;
    exports com.example.data.internal to com.example.test;
    
    opens com.example.data.entity to org.hibernate.orm.core;
}
```

### 10.3 Модуль с провайдерами сервисов

```java
/**
 * Система плагинов для расширяемой функциональности.
 * <p>

 * будут автоматически обнаружены и загружены.

 *
 * @since 3.5
 * @see com.example.plugin.Plugin

module com.example.plugin.api {
    exports com.example.plugin;
    
    uses com.example.plugin.Plugin;
}
```

## 11. Использование блочных тегов

### 11.1 Стандартные блочные теги

Блочные теги должны появляться после основного описания и следовать строгому порядку:

**Стандартный порядок:**
1. `@param` (методы и конструкторы, параметры типов)
2. `@return` (только для методов)
3. `@throws` или `@exception` (методы и конструкторы)
4. `@see`
5. `@since`
6. `@deprecated`

**Примечание:** `@author` и `@version` намеренно не перечислены, так как они не рекомендуются в современной разработке.

### 11.2 @param

Используется для параметров методов и конструкторов, параметров типов и компонентов записей:

```java
/**
 * Сохраняет пару ключ-значение в кэше.
 *
 * @param <K> тип ключей, поддерживаемых этим кэшем
 * @param <V> тип сохраняемых значений
 * @param key ключ, с которым должно быть связано указанное значение,
 *            не должен быть null
 * @param value значение, которое должно быть связано с указанным ключом,
 *              null-значения разрешены
 * @throws NullPointerException если key равен null
 */
public <K, V> void put(K key, V value) {
    // реализация
}
```

### 11.3 @return

Используется для описания возвращаемого значения методов (не конструкторов и не void-методов):

```java
/**
 * Вычисляет среднее значение заданных чисел.
 *
 * @param numbers массив чисел для усреднения, не должен быть null или пустым
 * @return среднее арифметическое всех чисел в массиве
 * @throws IllegalArgumentException если numbers равен null или пустой
 */
public double calculateAverage(double[] numbers) {
    // реализация
}
```

### 11.4 @throws / @exception

Документирует исключения, которые могут быть выброшены:

```java
/**
 * Читает содержимое файла.
 *
 * @param filePath путь к файлу для чтения, не должен быть null
 * @return содержимое файла в виде строки, никогда не null
 * @throws NullPointerException если filePath равен null
 * @throws FileNotFoundException если файл не существует
 * @throws IOException если происходит ошибка ввода-вывода во время чтения
 * @throws SecurityException если существует менеджер безопасности и он запрещает
 *         доступ на чтение к файлу
 */
public String readFile(Path filePath) throws IOException {
    // реализация
}
```

**Примечание:** `@throws` и `@exception` являются синонимами; используйте `@throws` для согласованности.

### 11.5 @see

Создает ссылки на связанные элементы:

```java
/**
 * Шифрует конфиденциальные данные, используя алгоритм AES-256.
 *
 * @param plaintext данные для шифрования, не должны быть null
 * @param key ключ шифрования, должен быть ровно 32 байта
 * @return зашифрованные данные
 * @throws NullPointerException если plaintext или key равен null
 * @throws IllegalArgumentException если длина key не равна 32 байтам
 * @see #decrypt(byte[], byte[])
 * @see EncryptionUtils
 * @see <a href="https://ru.wikipedia.org/wiki/Advanced_Encryption_Standard">AES в Википедии</a>
 */
public byte[] encrypt(byte[] plaintext, byte[] key) {
    // реализация
}
```

### 11.6 @since

Указывает, когда элемент был добавлен:

```java
/**
 * Проверяет адрес электронной почты, используя правила RFC 5322.
 *
 * @param email адрес электронной почты для проверки, не должен быть null
 * @return true, если email допустим, иначе false
 * @since 2.1
 */
public boolean isValidEmail(String email) {
    // реализация
}
```

### 11.7 @deprecated

Отмечает устаревшие элементы и предлагает альтернативы:

```java
/**
 * Вычисляет хэш-код, используя алгоритм MD5.

 * @return хэш MD5
 * @throws NullPointerException если input равен null
 * @deprecated начиная с версии 3.0, MD5 криптографически взломан. Используйте

    // реализация

/**

 */

    // реализация
}
```

## 12. Использование встроенных тегов

Встроенные теги могут появляться в любом месте описания или комментариев блочных тегов.

### 12.1 {@code}

Используется для фрагментов кода, ключевых слов и идентификаторов:
- Отображает текст моноширинным шрифтом
- Отключает интерпретацию HTML
- Не нужно экранировать специальные символы HTML внутри

**Пример:**
```java
/**
 * Проверяет, содержит ли коллекция указанный элемент.
 * <p>
 * Этот метод возвращает {@code true}, если эта коллекция содержит хотя бы
 * один элемент {@code e} такой, что {@code Objects.equals(o, e)}.
 *
 * @param element элемент для поиска
 * @return {@code true}, если элемент найден, {@code false} в противном случае
 */
public boolean contains(Object element) {
    // реализация
}
```

### 12.2 {@literal}

Аналогичен `{@code}`, но отображается обычным шрифтом (не моноширинным):
- Отключает интерпретацию HTML
- Используйте для отображения специальных символов без семантики кода

**Пример:**
```java
/**
 * Сравнивает две строки лексикографически.
 * <p>
 * Возвращает отрицательное целое число, если {@literal this < that}, ноль, если
 * {@literal this == that}, или положительное целое число, если {@literal this > that}.
 *
 * @param other строка для сравнения
 * @return результат сравнения
 */
public int compareTo(String other) {
    // реализация
}
```

### 12.3 {@link} и {@linkplain}

Создает гиперссылки на другие документированные элементы:
- `{@link}` отображается моноширинным шрифтом (шрифт кода)
- `{@linkplain}` отображается обычным шрифтом

**Синтаксис:**
- `{@link ClassName}` - ссылка на класс
- `{@link ClassName#methodName}` - ссылка на метод
- `{@link ClassName#methodName(Type)}` - ссылка на конкретную перегрузку
- `{@link #methodName}` - ссылка на метод в текущем классе
- `{@link ClassName текст метки}` - пользовательский текст ссылки

**Пример:**
```java
/**
 * Специализированная реализация списка.
 * <p>
 * Этот класс расширяет {@link java.util.ArrayList} и предоставляет дополнительную
 * функциональность для массовых операций. Для стандартных операций со списками см.
 * {@link java.util.List}.
 * <p>
 * Используйте {@link #addAll(Collection)} для эффективной массовой вставки, или
 * {@linkplain #addOne(Object) метод добавления одного элемента} для
 * отдельных элементов.
 *
 * @param <E> тип элементов в этом списке
 * @see java.util.ArrayList
 * @see java.util.List
 */
public class EnhancedList<E> extends ArrayList<E> {
    // реализация
}
```

### 12.4 {@value}

Отображает значение константы:

**Пример:**
```java
/**

    /**

 * с таймаутом {@value AppConfig#DEFAULT_TIMEOUT} миллисекунд.
 *
 * @return true, если подключение успешно, иначе false
 */
public boolean connect() {
    // реализация
```

Копирует документацию из переопределенного метода или реализованного интерфейса:

## 13. Хорошие и плохие примеры

### 13.1 Документация класса

#### ❌ Плохой пример

```java
/**
 * Сервис пользователей.
 * 
 * @version 1.0
 * @author Иван
 */
public class UserService {
    public void addUser(String name, String email) {
        // реализация
    }
}
```

**Проблемы:**
- Нет точки в конце резюмирующего предложения
- Ненужные теги `@version` и `@author` (современный анти-паттерн)
- Слишком кратко, нет полезной информации
- Метод не документирован
- Нет информации о поведении или ограничениях

#### ✅ Хороший пример

```java
/**
 * Предоставляет бизнес-логику для управления учетными записями пользователей.
 * <p>
 * Этот сервис обрабатывает создание, получение, обновление и удаление
 * пользователей. Он применяет бизнес-правила, такие как уникальность имени пользователя
 * и валидация электронной почты.
 * <p>
 * Все методы потокобезопасны и транзакционны.
 *
 * @since 1.0
 * @see UserRepository
 * @see UserValidator
 */
public class UserService {
    
    /**
     * Добавляет нового пользователя в систему.
     * <p>
     * Этот метод валидирует входные параметры, проверяет уникальность
     * имени пользователя и электронной почты, и сохраняет новую учетную запись пользователя.
     *
     * @param name полное имя пользователя, не должно быть null или пустым
     * @param email адрес электронной почты, не должен быть null и должен быть допустимым
     * @return созданный пользователь с сгенерированным ID
     * @throws NullPointerException если name или email равен null
     * @throws IllegalArgumentException если name пустое или email недопустимый
     * @throws DuplicateEmailException если электронная почта уже зарегистрирована
     */
    public User addUser(String name, String email) {
        // реализация
    }
}
```

### 13.2 Документация записи

#### ❌ Плохой пример

```java
/**
 * Точка
 * @param x x
 * @param y y
 */
public record Point(double x, double y) {}
```

**Проблемы:**
- Нет точки в конце резюме
- Описания параметров бесполезны
- Нет информации об использовании или ограничениях

#### ✅ Хороший пример

```java
/**
 * Представляет неизменяемую точку в двумерном декартовом пространстве.
 * <p>
 * Эта запись обеспечивает value-based семантику с автоматическими
 * реализациями {@code equals()}, {@code hashCode()} и {@code toString()}.
 * <p>
 * Пример использования:
 * <pre>{@code
 * Point origin = new Point(0.0, 0.0);
 * Point p = new Point(3.0, 4.0);
 * double distance = origin.distanceTo(p); // 5.0
 * }</pre>
 *
 * @param x x-координата, может быть любым конечным или бесконечным значением double
 * @param y y-координата, может быть любым конечным или бесконечным значением double
 * @since 2.0
 */
public record Point(double x, double y) {
    
    /**
     * Вычисляет евклидово расстояние от этой точки до другой.
     *
     * @param other другая точка, не должна быть null
     * @return расстояние между точками
     * @throws NullPointerException если other равна null
     */
    public double distanceTo(Point other) {
        double dx = this.x - other.x;
        double dy = this.y - other.y;
        return Math.sqrt(dx * dx + dy * dy);
    }
}
```

### 13.3 Документация аннотации

#### ❌ Плохой пример

```java
/**
 * Помечает как кэшируемое
 */
@interface Cached {
    int value();
}
```

**Проблемы:**
- Нет точки в конце
- Нет объяснения, что делает и как использовать
- Элемент не документирован

#### ✅ Хороший пример

```java
/**
 * Указывает, что результаты метода должны кэшироваться.
 * <p>
 * При применении к методу фреймворк будет кэшировать возвращаемое значение
 * на основе параметров метода. Последующие вызовы с теми же параметрами
 * вернут кэшированное значение без выполнения метода.
 * <p>
 * Пример использования:
 * <pre>{@code
 * @Cached(ttl = 3600)
 * public User findUserById(Long id) {
 *     return database.query(id);
 * }
 * }</pre>
 *
 * @since 2.5
 * @see CacheManager
 */
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Cached {
    
    /**
     * Время жизни для кэшированных значений в секундах.
     * <p>
     * После этой длительности кэшированное значение истекает и метод
     * будет выполнен повторно при следующем вызове. Должно быть положительным.
     * <p>
     * По умолчанию 300 секунд (5 минут).
     *
     * @return TTL в секундах
     */
    int ttl() default 300;
}
```

## 14. Частые ошибки и чек-лист лучших практик

### 14.1 Частые ошибки doclint

#### Отсутствующие элементы

- [ ] **Отсутствующий Javadoc-комментарий**: Каждый public/protected класс, интерфейс, перечисление, запись, аннотация, метод и конструктор должны иметь Javadoc
- [ ] **Отсутствующее резюмирующее предложение**: Первое предложение должно заканчиваться точкой, восклицательным или вопросительным знаком
- [ ] **Отсутствующий тег @param**: Каждый параметр (включая параметры типов и компоненты записей) должен быть документирован
- [ ] **Отсутствующий тег @return**: Каждый не-void метод должен иметь @return
- [ ] **Отсутствующий тег @throws**: Все объявленные исключения и важные исключения времени выполнения должны быть документированы

#### Ошибки HTML

- [ ] **Незакрытые HTML-теги**: Все теги должны быть правильно закрыты (например, `<p>...</p>`, `<b>...</b>`)
- [ ] **Неправильные HTML-сущности**: Используйте `&lt;`, `&gt;`, `&amp;` или `{@literal}` для специальных символов
- [ ] **Устаревшие HTML-теги**: Избегайте `<font>`, `<center>` и т.д.

#### Ошибки ссылок

- [ ] **Недопустимая ссылка @see**: Убедитесь, что ссылки на классы и методы существуют и полностью квалифицированы, если необходимо
- [ ] **Недопустимая ссылка {@link}**: Проверьте правописание и включите типы параметров для перегруженных методов
- [ ] **Битые внешние ссылки**: Проверьте URL в тегах `<a href="...">`

#### Ошибки структуры

- [ ] **Неправильный порядок тегов**: Следуйте стандартному порядку (param, return, throws, see, since, deprecated)
- [ ] **Висячий Javadoc**: Убедитесь, что комментарий непосредственно присоединен к элементу без пустых строк
- [ ] **Javadoc не на том элементе**: Не размещайте теги уровня класса на методах или наоборот

### 14.2 Чек-лист лучших практик

#### Стиль написания

- [ ] Используйте **настоящее время** (например, "Возвращает пользователя", а не "Вернет пользователя")
- [ ] Используйте **третье лицо** (например, "Вычисляет сумму", а не "Вычислите сумму")
- [ ] Начинайте описания методов с **глагола** (например, "Проверяет", "Создает", "Получает")
- [ ] Будьте **кратки**, но **полны** - включайте всю необходимую информацию без избыточности
- [ ] Избегайте **деталей реализации** - описывайте что, а не как

#### Содержание

- [ ] Документируйте **предусловия** (что должно быть истинным перед вызовом)
- [ ] Документируйте **постусловия** (что будет истинным после вызова)
- [ ] Документируйте **побочные эффекты** (изменения состояния, операции ввода-вывода и т.д.)
- [ ] Документируйте **потокобезопасность** для конкурентного кода
- [ ] Документируйте **обработку null** (могут ли параметры быть null? Может ли возвращаемое значение быть null?)
- [ ] Документируйте **пустые случаи** (пустые коллекции, нулевые значения и т.д.)
- [ ] Включайте **примеры использования** для сложных API

#### Параметры и возвращаемые значения

- [ ] Каждый @param должен объяснять **что** представляет параметр и **ограничения** на его значение
- [ ] Используйте "не должен быть null" или "может быть null" для каждого ссылочного параметра
- [ ] Указывайте **диапазоны** для числовых параметров (например, "должен быть положительным", "между 0 и 100")
- [ ] Объясняйте специальные значения @return (null, пустое, -1 и т.д.)
- [ ] Используйте "никогда не null" или "может быть null" для возвращаемых значений

#### Исключения

- [ ] Документируйте **все проверяемые исключения** в объявлении throws
- [ ] Документируйте **важные исключения времени выполнения** (NullPointerException, IllegalArgumentException и т.д.)
- [ ] Объясняйте **условие**, вызывающее каждое исключение
- [ ] Используйте конкретные типы исключений, а не общий Exception

#### Теги и ссылки

- [ ] Используйте `{@code}` для элементов кода (ключевые слова, имена классов, переменные)
- [ ] Используйте `{@link}` для ссылок на другие документированные элементы
- [ ] Используйте `{@literal}` для специальных символов в обычном тексте
- [ ] Включайте ссылки `@see` на связанные классы и методы
- [ ] Отмечайте устаревшие элементы и тегом `@deprecated`, и аннотацией `@Deprecated`
- [ ] Всегда предлагайте **альтернативы** в комментариях @deprecated

#### Современные практики

- [ ] **Избегайте тегов @author** - история Git предоставляет лучшую информацию
- [ ] **Избегайте тегов @version** - Используйте версионирование системы сборки вместо этого
- [ ] Используйте `@since` для указания, когда функции были введены
- [ ] Документируйте компоненты записей в Javadoc на уровне класса
- [ ] Предоставляйте package-info.java для нетривиальных пакетов
- [ ] Рассмотрите документацию module-info.java для модулей Java 9+

#### Команды валидации

Перед коммитом проверьте ваш Javadoc:

```bash
# Генерация Javadoc с включенным doclint (все проверки)
javadoc -Xdoclint:all -d target/javadoc -sourcepath src/main/java \
    -subpackages com.example

# С конкретными проверками doclint
javadoc -Xdoclint:html,syntax,reference -d target/javadoc \
    -sourcepath src/main/java -subpackages com.example

# С Maven
mvn javadoc:javadoc -Djavadoc.lint=all

# С Gradle
./gradlew javadoc -Djavadoc.lint=all
```

### 14.3 Краткая справка: Порядок тегов

Для **классов, интерфейсов, перечислений, записей, аннотаций**:
```
@param (для параметров типов и компонентов записей)
@see
@since
@deprecated
```

Для **методов и конструкторов**:
```
@param (все параметры)
@return (только методы)
@throws (все исключения)
@see
@since
@deprecated
```

### 14.4 Чек-лист перед коммитом

Перед коммитом кода с Javadoc:

1. [ ] Все public/protected элементы имеют Javadoc
2. [ ] Все резюмирующие предложения заканчиваются правильной пунктуацией
3. [ ] Все параметры (включая параметры типов) документированы
4. [ ] Все исключения документированы
5. [ ] HTML-теги правильно закрыты
6. [ ] Ссылки и ссылки действительны
7. [ ] Нет предупреждений или ошибок doclint при запуске с `-Xdoclint:all`
8. [ ] Примеры кода компилируются и работают
9. [ ] Правописание и грамматика правильны
10. [ ] Документация соответствует фактическому поведению
11. [ ] Нет тегов `@author` или `@version` (если не требуется политикой)
12. [ ] Компоненты записей документированы в Javadoc на уровне класса
13. [ ] package-info.java существует для публичных пакетов

## Заключение

Это руководство обеспечивает всеобъемлющий охват лучших практик Javadoc, которые соответствуют требованиям `doclint` для **всех** типов элементов Java:

- ✅ **Классы и интерфейсы** - Назначение, контракты, использование
- ✅ **Перечисления** - Константы, поля, методы
- ✅ **Записи** - Компоненты, валидация, методы
- ✅ **Аннотации** - Элементы, использование, примеры
- ✅ **Поля** - Константы, поля экземпляра
- ✅ **Методы и конструкторы** - Параметры, возвращаемые значения, исключения
- ✅ **Generic-типы** - Параметры типов, границы, wildcards
- ✅ **Пакеты** - Документация package-info.java
- ✅ **Модули** - Документация module-info.java

**Ключевые выводы:**

1. **Современный подход**: Избегайте `@author` и `@version` - они являются нагрузкой на поддержку
2. **Полное покрытие**: Документируйте ВСЕ элементы public/protected API
3. **Обработка null**: Всегда указывайте, могут ли параметры/возвращаемые значения быть null
4. **Примеры**: Предоставляйте примеры использования для сложных API
5. **Соответствие doclint**: Валидируйте с `-Xdoclint:all` перед коммитом

Помните: Хорошая документация так же важна, как и хороший код. Хорошо документированные API легче использовать, поддерживать и развивать. Инвестируйте время в написание ясных, полных Javadoc-комментариев - ваши пользователи (и будущее "я") будут вам благодарны!
